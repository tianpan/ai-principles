**项目部工程管理需求报告**

## 1. 项目背景

### 1.1 背景说明

港华智慧能源有限公司（简称"港华"）是中华煤气旗下专注于中国城市燃气及智慧能源业务的上市公司，旗下拥有多家燃气运营公司及工程服务子公司。在港华工程服务体系中，**卓裕（广东）工程建设有限公司**（简称"卓裕"）是港华通过"港华燃气投资有限公司"100%控股的专业工程公司，承担燃气、水务及市政基础设施项目的工程统筹、技术管理与总包管理职责，是港华体系内工程标准与管理的核心平台。 **江苏金卓建设工程有限公司**（简称"金卓"）是位于江苏南京的市政与土木工程类施工企业，作为港华体系内的一线施工承包单位，负责城市燃气设施更新、新建运营大楼等工程的现场施工与交付。 本系统将服务于"港华—卓裕—金卓"这一工程服务链条，支持项目策划、工程分包、实施监控、安全与质量及结算等环节的数字化协同，提升港华体系在工程管理与施工执行上的标准化与协同效率。

### 1.2 主要参与方与系统角色

| 主体 | 在港华体系中的角色 | 在系统中的主要定位与功能 |
| --- | --- | --- |
| 港华（港华智慧能源 / 港华燃气投资） | 集团工程投融资与整体管控主体，制定工程管理制度与标准 | 作为"集团管理与决策层"，负责项目立项审批、工程标准配置、预算控制、供应商管理、全局报表与绩效监控。 |
| 卓裕（广东）工程建设有限公司 | 港华全资工程服务公司，负责工程规划、技术方案、工程总包与项目统筹管理 | 作为"工程总包与管理平台"，负责项目承接、工程分包、进度与安全质量管理、合同管理、结算发起及工程数据中枢。 |
| 江苏金卓建设工程有限公司 | 港华系工程承包商，承担一线施工执行任务 | 作为"施工承包实施方"，负责项目现场执行、分包组织、进度上报、质量安全记录、工单填报与结算申请。 |

### 1.3 项目目标

本项目主旨在于通过APP的利用，进行项目部精细化管理，提升项目部施工安全、材料可控、资料准确性和人员工效；是金卓建设全面预算管理的一环。同时通过APP与合作项目的分包单位进行管理互动，提升金卓项目部的整体管理水平，提高项目甲方的满意度。

## 2. 已确认的关键约束

> 以下信息经业务部门确认，直接影响系统设计方案。

### 2.1 系统定位

- **独立系统**：当前无 ERP、OA 等现有系统，本期不与外部系统对接。未来可能需要与 ERP 集成，架构上需预留接口。
- **本期范围明确**：合同管理、质量检查/验收、安全事故上报、成本核算、消息通知均不在本期范围内。仅聚焦四大核心模块。（审核超时提醒通过 APP/PC 后台内的待办列表实现，不涉及独立的消息推送模块。）
- **移动端 + PC 后台**：班组长通过 APP（安卓）进行现场操作；资料员通过 PC 后台进行资料整理和汇总；一线施工人员仅在安全学习时使用自有手机。

### 2.2 核心用户与设备

- **核心用户**：班组长和技术人员。一线施工人员非本期重点，仅在安全学习场景下使用。
- **设备条件**：班组长使用自有安卓手机（项目部给予话费补助），不统一配发。
- **离线支持**：采用**只读离线模式**。离线时班组长只能查看已下载的数据，不能新增记录。新增操作需要在线状态。高风险作业在没有网络信号时允许开工，事后补录。
- **视频监控**：一期**不含视频监控对接**。APP 仅记录高风险作业的开工/完工时间和文字描述，视频监控由项目部现有设备独立管理，后续再评估系统对接。
- **照片管理**：每模块每日设置照片上传上限（如考勤 1 张、进度 5 张、施工记录 10 张），具体数量可商榷调整。
- **需注意**：分包单位的班组长无法执行手机配发政策，系统设计需考虑 BYOD 场景。

### 2.3 交付策略

- **优先级**：考勤 > 进度 > 材料 > 竣工资料
- **分期交付**：接受分期上线，先在一个项目部试点验证，再全面推广。
- **目标**：尽快交付可用版本。

### 2.4 试点项目情况

- **团队规模**：中型，3-5 个班组，每个班组 5-15 人
- **工期**：1-3 个月
- **分包单位**：通常 1-3 个分包单位同时在一个项目部

## 3. 角色与权限体系

### 3.1 系统角色定义

| 角色 | 主要职责 | 操作终端 | 备注 |
|------|----------|----------|------|
| 金卓/卓裕管理层 | 查看全局数据，监督各项目部进度与安全 | PC 后台 / APP | 指定管理人员可查看所有项目部的整体数据 |
| 项目经理 | 每日审核确认（含退回修改、补充填写）、统筹安排、竣工管理、竣工资料提交倒计时考核 | APP + PC 后台 | 管理整个项目部下所有单项工程，统一审核各班组长数据；不可兼任班组长；超过 7 天未审核则通知项目管理部 |
| 班组长 | 每日登记（考勤、材料、进度、施工记录）、竣工草图绘制 | APP（安卓） | 可能在小规模项目中代行项目经理职责 |
| 资料员 | 资料汇总整理、竣工图绘制、材料用量核准、提交监理/甲方签字、配合项目经理配置项目工程量指标 | PC 后台为主 | 可能与班组长兼任（少见） |
| 一线施工人员 | 参加早会、安全学习 | 自有手机（仅安全学习） | 非本期重点用户 |
| 分包单位班组长 | 与金卓班组长功能完全一致，仅归属不同班组 | APP（安卓） | 分包承担的工作作为独立单项工程，分包班组长是该项目的指定班组长，由金卓项目经理统一审核 |

### 3.2 数据权限规则

- **金卓/卓裕管理层**：可查看所有项目部的整体数据
- **项目经理**：可查看和审核所属项目部下所有单项工程的数据
- **项目部层级**：只能查看本项目的数据（数据隔离）
- **班组长**：只能查看和管理本班组的当日数据
- **分包单位班组长**：分包承担的工作作为独立单项工程，权限等同于金卓班组长，仅管理其负责的单项工程

### 3.3 角色兼任与班组长指派规则

- **一项目一班组长**：每个单项工程指定**一名班组长**全权负责该项目的全部工程内容，不按分部分项拆分给多个班组长。班组长根据其特长和管理能力，被指派负责不同规模和工艺的项目
- **分包独立项目**：分包单位承担的工作作为独立的单项工程，分包班组长是该项目的指定班组长，由金卓项目经理统一审核
- 项目经理不可兼任班组长
- 资料员与班组长可能兼任（少见，但需支持）
- 小规模项目（如定向钻）：分包的班组长可能代行现场项目经理职责，需要在项目创建时灵活指定角色

### 3.4 备案人员管理

- **管理级别**：人员清单按**项目部级**维护。项目部统一前期录入所有人员信息，该项目部管辖的多个项目共享该人员库
- **跨项目规则**：同一人员**允许跨项目**（如张三可同时参与 A 项目和 B 项目），项目部灵活安排具体施工人员
- **班组组成**：班组是**灵活变动**的，非固定编制。每个单项工程指定一名班组长，负责该项目全部工程内容（不做分部分项拆分）。班组长根据特长和管理能力被指派不同规模和工艺的项目
- **实际人员认定**：以当日考勤打卡记录为准，当日实际进场作业人员即为该日班组成员
- **组建流程**：项目开工时从项目部备案人员中选定组建施工团队，施工过程中人员可灵活调整
- **备案内容**：录入人员基本信息、岗位、资格证书等。一期不录入指纹信息（指纹打卡为二期评估项）

### 3.5 项目创建与生命周期

- **创建人**：项目部技术人员根据项目经理口头指令，在 PC 后台创建项目
- **创建时必填字段**：项目名称、工期（开始/结束日期）、特殊说明、指派班组长
- **项目完工后处理**：项目结算后数据变为**只读不可编辑**，但仍可查看。当前不做归档功能
- **用户账号管理**：由管理员在 PC 后台统一创建所有用户账号，分配角色和所属项目部

## 4. 业务需求（四大模块）

### 4.1 安全与考勤管理

**目的：** 形成有效的班组安全管理系统，以班前早会为考勤的硬性条件，通过日常、持续的安全知识学习，提升一线施工人员安全意识和安全能力。通过 APP 对高风险作业进行全过程记录管控。

**核心关注：** 安全管理是本项目最核心的痛点，需要实时监管，每一个环节的管控。

**业务描述：**

- 项目开工进场前，设定该项目整体时间周期指标，各项工作项工程量指标。
- 从备案人员清单中，选定人员组建该项目施工团队。
- **班前早会流程**（班组长手机操作）：
  - 班组长组织晨会和安全交底
  - 按照金卓建设标准的作业安全要求进行宣贯，使用**分类安全交底模板**（根据作业类型使用不同模板，如高空作业、动火作业、有限空间作业等各有专门的交底表）
  - 班组长在手机上**手写电子签名**确认（安全交底记录、高风险作业确认单）。仅班组长签名即可，施工人员不需逐一签名。签名目的是通过反复的安全告知，提升施工人员安全意识和能力，港华安全管理体系认可手机屏幕手写签名作为有效记录。
  - 参会人员考勤确认
  - 班组长从备案人员列表中**手动勾选**实际参会人员（一期方案，二期评估是否升级为指纹打卡机）
- **考勤方案（分阶段）：**
  - **一期：拍照 + GPS 定位 + 班组长确认。** 班组长拍早会现场照片，系统记录 GPS 位置和时间，班组长确认参会人员名单。零硬件成本，快速上线。
  - **二期：评估是否升级为独立指纹打卡机。** 试点运行后根据实际需求决定是否采购独立指纹设备（约 500-2000 元/台），系统已预留指纹接口。
- **考勤规则：** 只有参与班前早会的一线施工人员才计考勤，考勤数据作为工资结算的依据。核心目的是安全（督促施工人员参加早会），不单是考勤管理。
- **高风险作业管理**：APP 记录高风险作业的开工/完工时间和文字描述。一期不含视频监控对接，视频监控由项目部现有设备独立管理。**无网络信号时允许开工，事后补录。**
- 项目经理每日进行确认（审核通过 / 退回修改 / 补充填写）。

### 4.2 进度与工效管理

**目的：** 根据工程项目的工期要求，动态调整每日人员安排，以期按时完工。同时通过本APP，对工程现场施工人员的安排进行评核、反馈，减少窝工、烂工的情况，提升项目部的工效。

**核心关注：** 工程量编制确认滞后、遗漏问题较多，需要通过每日实时记录来改善。

**业务描述：**

- 班组长早会前每日进行现场施工人数登记，并匹配核查现场当日作业人员是否在备案清单中，关键岗位是否持证上岗。
- **班组长每日施工进度记录**，包含以下内容：
  - **具体工程量数值**：记录各项工作项当日完成量（如焊接完成 120 米、开挖完成 80 米）
  - **现场照片**：拍摄施工进展照片作为凭证
  - **自动计算完成百分比**：根据项目开工前录入的各项工作项工程量指标，系统自动累计计算各工作项完成比例。**项目整体进度按权重加权计算**：为每个工作项设定权重（建议按预算金额占比），加权汇总得出项目整体完成百分比
- **施工图区域标注：** 一期不要求班组长在施工图上做区域标注（班组长不具备电子画图能力，手机操作不便）。APP 落地使用顺畅后，再考虑增加轻量级标注功能作为二期优化。
- 项目经理根据工程进展情况每日进行确认，统筹各项工程工作安排。

**项目工程量指标配置：**
- **工程量层级**：采用**扁平工作项列表**（一级结构），不做分部分项层级统一管理。每个项目由一名班组长负责全部工程内容，根据实际工程内容列出工作项（如"中压管线焊接"、"阀门安装"、"管沟开挖"等），每项设定目标工程量、单位和**权重**（建议按预算金额占比，用于计算项目整体完成百分比）。
- **配置人**：资料员配合项目经理完成
- **配置时机**：项目开工前在 PC 后台录入各项工作项工程量指标
- **调整规则**：施工过程中可调整（如设计变更导致工程量增减）

### 4.3 材料和设备管理

**目的：** 记录从项目部二级库领料至现场的材料数量、工程完工后退料情况，同时进行施工现场的设备租赁、乙供材采购数量登记，评核项目部单项工程的用料符合度。通过日常的材料和设备管控，降低材料遗失的情况，提升设备效能。

**核心关注：** 当前未进行领后使用跟踪，存在材料遗失情况，需考核责任。

**现状：**
- 项目部二级仓库为纯手工台账，无库存管理系统
- 领料时无编码或条码，手写品名和数量
- 设计文件中有现成的材料清单（BOM），可作为预算基准

**业务描述：**

- **材料登记方式：按领料单逐笔记录**。每次领料对应一张领料单，记录单号、品名、规格、数量。需细化到规格级别（如 DN100 镀锌钢管 30 米，DN200 无缝钢管 20 米）。
- **录入便捷性：历史记录快速复制。** 班组长可以复制昨天的领料记录，只需修改数量即可，适合每天领类似材料的场景，大幅减少重复输入。
- 班组长每日登记自项目部二级仓库领用至工程现场的材料数量。
- 班组长每日登记施工现场设备租赁台班（吊车、挖机、高空作业车等）。
- 班组长每日登记现场采买材料的数量（沙石、水泥、钢材、气体等）。
- 工程项目完工后，班组长登记退回项目部二级仓的材料（含现场采买材料）。
- 项目经理每日进行确认（审核通过 / 退回修改 / 补充填写）。
- 工程完工后，资料员根据竣工图统计实际材料用量，与 APP 中记录的领用/采买量进行比对核准，确保材料和设备使用合理。

**材料核销逻辑：** 领用量 - 退料量 = 实际使用量，再与竣工图统计量做比对。差异超出阈值时标记异常，需要项目部说明。**阈值标准：** 一般材料差异超过实际用量 2% 即标记异常；阀门类材料差异阈值为 0%（不允许任何偏差）。从零开始的材料管理闭环，一期只做领料/退料/采买记录 + 与 BOM 清单的比对，不做库存管理。

### 4.4 现场记录和竣工资料管理

**目的：** 通过日常施工记录，避免工程量漏记、多记，确保工程竣工资料的准确性，同时通过班组长与资料员的共享、互助平台，提升资料编制工效，及时进行竣工资料、结算提交。

**核心关注：**
- 存在多次现场核对，隐蔽工程无法核对，现场资料缺失
- 通过每日实时记录（工程量 + 影像凭证）来解决竣工资料滞后和遗漏

**业务描述：**

- **施工图来源：** 纸质蓝图 + PDF 文件。项目开工时，施工图以纸质蓝图和 PDF 两种形式提供。APP 需支持 PDF 导入查看，同时班组长对照纸质蓝图施工。
- **施工记录表格：** 使用企业自有表格（非国标），侧重于工程量的记录。需由业务方提供样例表格以设计 APP 表单。
- **班组长每日登记现场施工记录**：按企业自有竣工资料表格，准确记录高度、深度、宽度、长度等数据。侧重于工程量及影像记录凭证。
- **资料员每日提取施工记录**：从系统中提取班组长提交的记录，整理完善后提交监理、甲方签字确认。
- **签字方式：** 线下签字为主。APP 记录签字进度状态（已签/未签），不强制要求电子签章。可支持拍照上传签字文件作为存档。
- **竣工草图绘制**（班组长职责）：
  - **主要方式：** 拍手绘草图照片上传（操作便捷，适合班组长实际操作水平）
  - **辅助方式：** 在施工图（PDF）上简单标注（画圈、画线标注完成区域，不做复杂 CAD 级别标注）
  - 出现变更时准确标明，特别是隐蔽工程
  - **注意：** 班组长大部分不具备电子画图能力，手机屏幕上电子图标注极其不便，系统应优先支持拍照上传
- **竣工图绘制**（资料员职责）：工程项目完工后，资料员提取现场草图，进行竣工图绘制（必要时现场确认）。
- 项目经理每日进行确认（审核通过 / 退回修改 / 补充填写），工程完工后安排资料员对实际材料使用和领用（采买）材料进行核准。
- 项目经理通过工程完工日期确认，进行竣工资料提交倒计时管理，对资料员进行考核。**考核期限：竣工资料 30 日内提交，结算资料 45 日内提交。**

## 5. 项目经理审核机制

> 经确认，项目经理"每日确认"包含以下内容：

**审核操作：**
- **审核确认**：查看班组长提交的数据，确认无误后点击"审核通过"
- **退回修改**：如果数据有问题，可以退回班组长修改后重新提交
- **补充填写**：项目经理自己也需要补充一些数据或说明

**审核通过后的数据修正：**
- **追加修正**：审核通过后不允许删除或直接修改原记录，但可以追加一条"修正记录"说明更正内容和原因
- 系统保留完整的审计轨迹（原记录 + 修正记录），确保竣工资料数据可信

**每日操作流程（班组长）：**
- 系统采用**必填项引导**模式，首页显示"今日待填"清单：考勤⬜ 进度⬜ 材料⬜ 施工记录⬜
- 班组长逐项完成，不强制一次性填完，适合现场分段操作
- 每项独立提交，项目经理按模块分别审核

**时效管理：**
- 审核时效不严格，几天内确认即可（不要求当天完成）
- **超时提醒机制**：超过 7 天未审核，系统自动通知项目管理部（注意：通知项目管理部，不直接升级到金卓/卓裕管理层）
- 施工单位每周只休息一天，项目经理有足够时间处理审核

**审核范围：** 覆盖所有四个模块：考勤数据、进度记录、材料登记、施工记录。

## 6. 管理层报表需求

> 经确认，金卓和卓裕管理层最关注以下三类报表：

| 报表 | 内容 | 数据来源 |
|------|------|----------|
| 各项目进度总览 | 计划 vs 实际完成百分比（按权重加权计算），各项工作项进度对比 | 进度模块（基于项目开工前指标自动计算） |
| 安全事件汇总 | 安全交底完成率、高风险作业监控情况 | 考勤模块 + 安全交底记录 |
| 竣工资料提交进度 | 资料完成度、竣工倒计时 | 竣工资料模块 |

## 7. 核心痛点与系统价值映射

| 核心痛点 | 对应模块 | 系统如何解决 |
|----------|----------|-------------|
| 现场安全监督管理，需要实时监管每一个环节 | 安全与考勤 | 班前早会签到 + 分类安全交底模板 + 签名 + 高风险作业记录，每日流程闭环 |
| 工程量编制确认滞后、遗漏多 | 进度与工效 | 班组长每日实时记录工程量数值 + 照片，自动累计计算完成比例 |
| 材料领后无跟踪，存在遗失 | 材料与设备 | 按领料单逐笔记录 + 历史记录快速复制，领料→使用→退料全链路追踪 |
| 竣工资料编制耗时长，隐蔽工程难核对 | 现场记录与竣工资料 | 每日记录 + 草图/影像拍照，资料员实时提取整理，减少现场反复核对 |

## 8. 技术约束与架构要点

### 8.1 已确认的技术约束

| 约束项 | 说明 |
|--------|------|
| 客户端平台 | 安卓 APP（班组长），PC Web 后台（资料员、管理层） |
| iOS 支持 | 本期不需要 |
| 离线模式 | **只读离线**。离线时只能查看已下载的数据，不能新增记录。新增操作需在线 |
| 签名控件 | 需要支持手机屏幕手写签名（安全交底记录、高风险作业确认单）。港华安全管理体系认可手机手写签名 |
| 每日操作模式 | **必填项引导**：首页显示今日待填清单，班组长逐项完成，不强制一次性填完 |
| 考勤方案 | **分阶段实施**。一期：拍照 + GPS + 班组长从备案清单手动勾选参会人员（零硬件成本）；二期：评估独立指纹打卡机 |
| 视频监控 | **一期不含视频监控对接**。APP 仅记录高风险作业时间和描述，视频监控由项目部现有设备独立管理 |
| 草图交互 | 以拍照上传为主，轻量级 PDF 标注为辅 |
| 签字方式 | 线下签字 + APP 记录状态（不做电子签章） |
| 施工图查看 | 支持 PDF 导入查看（APP 端），纸质蓝图另行管理 |
| 安全交底 | 分类模板，根据作业类型匹配不同交底表 |
| 竣工记录表格 | 企业自有表格，需提供样例 |
| 材料记录 | 按领料单逐笔记录，细化到规格级别，支持历史记录快速复制 |
| 进度记录 | 工程量数值 + 照片，自动计算各工作项完成百分比 + 按权重计算项目整体进度；一期不做施工图区域标注 |
| 工程量结构 | **扁平工作项列表**（一级），不做分部分项层级统一管理。每个单项工程由一名班组长负责全部工程内容 |
| 高风险作业 | 无网络时允许开工，事后补录 |
| 项目指标配置 | 资料员配合项目经理录入，施工过程中可调整 |
| 审核超时 | 超过 7 天未审核自动通知项目管理部（通过 APP/PC 后台内待办/异常列表展示，不做独立消息推送） |
| 数据修正 | 审核通过后不允许直接修改，采用追加修正记录方式，保留完整审计轨迹 |
| 备案人员管理 | 按项目部级维护，同一人员允许跨项目 |
| 材料核销阈值 | 一般材料差异超过实际用量 2% 标记异常，阀门类材料阈值为 0% |
| 照片管理 | 每模块每日设置照片上传上限（如考勤 1 张、进度 5 张、施工记录 10 张），具体数量可商榷调整 |
| 用户账号 | 管理员在 PC 后台统一创建，分配角色和所属项目部 |
| 项目创建 | 项目部技术人员根据项目经理指令创建，必填：项目名称、工期、特殊说明、班组长指派 |
| 项目完工 | 结算后数据只读不可编辑，仍可查看，不做归档 |
| 竣工资料期限 | 竣工资料 30 日内提交，结算资料 45 日内提交，项目经理通过倒计时考核资料员 |
| 安全签名 | 仅班组长手写签名确认安全交底，施工人员不需逐一签名 |
| 分包项目 | 分包承担的工作作为独立单项工程，分包班组长为指定负责人，金卓项目经理统一审核 |
