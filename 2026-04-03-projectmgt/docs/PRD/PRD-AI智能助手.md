# 工程管家 AI 智能助手 PRD

> 版本: 1.0 | 日期: 2026-04-04 | 状态: 待评审

## 1. 背景与目标

### 1.1 现状分析

工程管家 V1.1 原型已实现四大业务模块（安全考勤、施工进度、材料设备、施工记录）的完整流程。但当前系统存在一个根本矛盾：

**班组长每天要填大量表单，但这些数据的价值只被"存档"和"审核"消耗了，没有产生更上层的洞察。**

```
当前数据流（单向、末端浪费）

  班组长手工填表 ──▶ 日报数据 ──▶ 项目经理审核 ──▶ 存档
       ↑                                      ↓
    效率低                              数据沉睡，无二次利用
    易出错                              没有预警，没有预测
    重复劳动                            经理只能逐条看
```

### 1.2 AI 整合的底层逻辑

AI 不是"加个聊天框"。核心是三个能力注入：

| 能力 | 解决什么 | 体现形式 |
|------|---------|---------|
| **理解** | 班组长不用学表单结构，说人话就能录入 | 对话式填表 |
| **推理** | 把散落的数据变成洞察和预警 | 智能审核、风险预测 |
| **生成** | 自动产出管理层需要的文档和简报 | 每日简报、报表增强 |

### 1.3 核心目标

1. **降低录入成本** — 从"填5张表"变成"说3句话"
2. **提升审核效率** — 从"逐条看25条"变成"只看5条异常"
3. **释放数据价值** — 从"数据沉睡"变成"每日智能简报"
4. **提前发现风险** — 从"出了问题才知道"变成"AI 提前预警"

**Prompt 设计要点**:
- System prompt 注入当前项目的工序列表、材料列表、历史记录
- Few-shot 示例：每种意图给 3 个典型输入/输出对
- 输出格式强制为 JSON Schema：`{ module, action, fields, confirm }`
- 不确定的字段主动追问，不猜

**前端实现**:
- 移动端：底部可拖拽浮窗（类似微信语音条），点击展开全屏对话
- 浮窗按钮固定在所有页面右下角
- 对话过程中可以切换到手动填表，两种方式数据互通

### 3.2 AI 智能审核（P0）

**场景**: 项目经理王经理打开审核工作台，不再需要逐条看 25 条记录。

#### 审核分级

```
原来：25条待审核 ──▶ 经理逐条看 ──▶ 通过/退回

AI后：25条待审核 ──▶ AI 预审 ──▶ 分类展示
                              │
                              ├── ✅ 18条 正常 ──▶ AI 自动通过（可撤回）
                              ├── ⚠️  5条 疑似异常 ──▶ 人工重点看
                              └── ❌ 2条 明显问题 ──▶ AI 退回+原因
```

#### 异常检测规则

| 检测维度 | 规则 | 示例 |
|---------|------|------|
| **数据突变** | 单日完成量 > 前7天日均的 3 倍 | 日常焊 30 米，突然报 150 米 |
| **逻辑矛盾** | 考勤人数与进度产出不匹配 | 2 人签到却完成了 5 人的量 |
| **材料异常** | 单日领料量超过项目剩余需求 | 项目还差 50 根管，领了 100 根 |
| **合规缺失** | 有高风险作业但无对应安全交底 | 动火作业无动火审批记录 |
| **证件过期** | 施工人员证件已过期仍在签到 | 焊工证到期仍参与焊接工序 |
| **进度偏离** | 实际进度偏离计划进度 >20% | 应完成 40% 实际只完成 20% |

#### PC 端审核界面改造

```

│  审核工作台                          🤖 AI 预审       │
├──────────────────────────────────────────────────────┤

│  ┌──────────────────────────────────────────────┐   │
│  │ 🤖 AI 预审结果                                │   │
│  │                                              │   │

│  │ ⚠️  疑似异常 5 条 — 请人工确认                │   │
│  │ ❌ 明显问题 2 条 — 已自动退回                 │   │
│  │                                              │   │
│  │ 一键通过全部正常项    查看异常详情             │   │

#### 技术方案

- **规则引擎**（优先）: 硬编码 6 类异常规则，阈值可配置。覆盖 80% 场景，零延迟。
- **AI 增强**（后续）: 对规则引擎标记的"疑似异常"，调用 LLM 做二次判断，分析是否为合理例外（如"集中备料"场景）。
- **审核反馈闭环**: 经理对 AI 判断的通过/推翻操作，作为训练数据存入 `ai_audit_logs` 表。

### 3.5 进度风险预测（P2）

**场景**: AI 基于历史数据，预测每个项目的延期概率和超预算风险。

#### 预测模型

```
输入：
  · 每日完成量序列（过去 N 天）
  · 目标总量
  · 剩余工期
  · 资源配置（人数、设备）

计算：
  1. 日均完成速度 = Σ(每日完成量) / N
  2. 预计完成天数 = 剩余量 / 日均速度
  3. 延期概率 = P(预计天数 > 剩余工期)
  4. 考虑加速因子（增加人员/设备）

输出：
  · 延期概率：高/中/低
  · 预计超期天数
  · 建议措施（增加N人或延长M天）
```

#### 风险看板

```

│  🎯 项目风险雷达                                  │
│                                                  │

│  YY路支管     🔴 高      🟡 中       72/100      │

### 3.6 拍照识图辅助（P2）

**场景**: 班组长拍照后，AI 自动识别照片内容，辅助填表。

#### 识别能力

| 拍照对象 | AI 识别 | 自动填充 |
|---------|---------|---------|
| 管道/管材 | 管材类型、管径 | 材料名、规格 |
| 焊缝 | 焊接质量、焊缝类型 | 施工记录·工序 |
| 管沟 | 深度、宽度（参考物对比） | 施工记录·尺寸 |
| 施工现场全景 | 施工类型、参与人数 | 考勤·人数校验 |
| 安全标识 | 是否齐全 | 安全合规检查 |

#### 技术方案

- 使用多模态 LLM（如 GPT-4V / Claude Vision）进行图像理解
- 照片上传时异步调用，结果以建议形式展示，用户确认后填入
- 渐进式实现：先做管材识别，再做焊缝检测

## 7. 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| LLM 响应延迟 >3 秒 | 对话体验差 | 流式输出 + 本地意图预判 |
| 意图识别准确率 <90% | 填错数据 | 关键操作需用户确认，可修改 |
| API 成本 | 运营成本 | Sonnet 级模型，控制 token 量 |
| 离线场景 | 工地信号差 | 规则引擎本地运行，LLM 可选 |
| 数据安全 | 施工数据敏感 | 私有化部署或数据脱敏 |

```
SYSTEM PROMPT:

你是"工程管家 AI 助手"，服务于建筑施工项目的班组长。
你的任务是帮助班组长快速完成每日登记工作。

## 可用模块
1. 考勤 — 安全签到、班前会、参会人员
2. 进度 — 各工序完成量登记
3. 材料 — 领料/退料/设备/采买

## 当前项目上下文
{project_context}

## 输出格式
返回 JSON：
{
  "intent": "create_record | query | unclear",
  "module": "考勤 | 进度 | 材料 | 施工记录 | null",
  "fields": { ... },
  "response": "对用户的回复",
  "needConfirm": true/false,
  "followUp": "追问问题（如有缺失字段）"
}

## 规则
- 不确定的字段必须追问，不要猜测
- 数量类字段必须有明确数字
- 位置字段必填
- 每次只处理一个模块
- 完成后主动提示下一个未填的模块
```
