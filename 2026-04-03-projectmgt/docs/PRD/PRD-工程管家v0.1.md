## 1. 产品概述

### 1.1 项目背景

#### 1.1.1 组织背景

本系统服务于"卓裕、金卓"工程管理链条，三方主体及系统定位如下：

| 主体 | 在港华体系中的角色 | 在系统中的定位 |
|------|-------------------|---------------|
| 港华智慧能源（港华燃气投资） | 集团工程投融资与整体管控主体，制定工程管理制度与标准 | 集团管理与决策层：项目立项审批、工程标准配置、预算控制、全局报表与绩效监控 |
| 卓裕（广东）工程建设有限公司 | 港华全资工程服务公司（100%控股），负责工程规划、技术方案、工程总包与项目统筹管理 | 工程总包与管理平台：项目承接、工程分包、进度与安全质量管理、合同管理、结算发起 |
| 江苏金卓建设工程有限公司 | 港华系一线施工承包商，承担市政与土木工程施工执行 | 施工承包实施方：项目现场执行、分包组织、进度上报、质量安全记录、工单填报与结算申请 |

#### 1.1.2 项目动因

金卓建设目前的项目部管理存在以下突出问题，直接影响施工安全、成本控制和工程交付质量：

| 核心痛点 | 具体表现 | 影响 |
|----------|---------|------|
| 现场安全监管难 | 班前早会缺乏记录、安全交底无留痕、高风险作业无法实时管控 | 安全隐患发现滞后，追责无依据 |
| 工程量编制确认滞后 | 依赖事后回忆和纸质记录，遗漏多、对不上 | 竣工资料反复核对，拖慢交付 |
| 材料领后无跟踪 | 二级仓库纯手工台账，无编码无条码，领后用量不明 | 材料遗失无法追责，成本失控 |
| 竣工资料编制耗时长 | 隐蔽工程无法事后核对，现场资料缺失，多次返场 | 竣工结算周期长，甲方满意度低 |

本项目主旨在于通过 APP 的利用，进行项目部精细化管理，提升项目部施工安全、材料可控、资料准确性和人员工效。同时本系统也是金卓建设**全面预算管理**的一环，通过与合作项目分包单位的数字化管理互动，提升金卓项目部的整体管理水平和甲方满意度。

#### 1.1.3 已确认的关键约束

| 约束项 | 说明 |
|--------|------|
| 独立系统 | 当前无 ERP、OA 等现有系统，本期不与外部系统对接。架构上预留接口，未来可对接 ERP |
| 移动端 + PC 后台 | 班组长 APP（安卓），资料员/管理层 PC Web 后台 |
| 设备条件 | 班组长使用自有安卓手机（BYOD），项目部给予话费补助，不统一配发 |
| 离线模式 | 只读离线：离线时仅查看已下载数据，不能新增记录 |
| 交付策略 | 分期上线，先在一个中型项目部试点验证，再全面推广 |
| 优先级 | 考勤 > 进度 > 材料 > 竣工资料 |

### 1.2 产品定位

**工程管家**是一款面向建筑工程项目部的**精细化管理工具**，以安卓 APP + PC Web 后台为载体，覆盖"卓裕、金卓"工程管理链条。系统聚焦**安全、进度、材料、竣工资料**四大核心场景，通过班组长每日移动端记录 + 项目经理审核闭环，解决现场安全监管难、工程量遗漏、材料失控、竣工资料滞后等痛点。

### 1.3 核心用户

- **主要用户**: 班组长（安卓 APP 日常操作）、项目经理（APP + PC 审核确认）
- **次要用户**: 资料员（PC 后台资料整理）、金卓/卓裕管理层（PC 后台报表查看）
- **边缘用户**: 一线施工人员（仅安全学习场景使用自有手机）

### 1.4 产品目标

| 目标 | 衡量方式 |
|------|----------|
| 提升施工安全 | 班前早会覆盖率 100%，安全交底记录完整可追溯 |
| 工程量零遗漏 | 班组长每日记录工程量，竣工资料与施工记录对齐 |
| 材料可控可追溯 | 领料→使用→退料全链路记录，差异超出阈值自动标记 |
| 竣工资料按时交付 | 竣工 30 日内、结算 45 日内提交，倒计时考核 |

### 1.5 系统边界

| 范围内 | 范围外（本期） |
|--------|----------------|
| 安卓 APP + PC Web 后台 | iOS 客户端 |
| 安全考勤、进度工效、材料设备、现场记录/竣工资料 | 合同管理、质量检查/验收、安全事故上报、成本核算 |
| 只读离线模式 | 全功能离线模式 |
| 线下签字 + APP 状态记录 | 电子签章系统 |
| `[AI Phase 1]` AI 对话填表、智能审核、每日简报、NL 查询 | AI 预测分析、工期/成本预警（Phase 5 规划） |
| APP 内待办/异常提醒 | 独立消息推送模块 |
| 手写电子签名（班组长） | 视频监控对接（一期） |
| 项目完工数据只读保留 | 数据归档功能 |

### 2.3 关键规则

- **一项目一班组长**: 每个单项工程指定一名班组长，负责全部工程内容，不按分部分项拆分
- **项目经理管项目部**: 项目经理管理整个项目部下的所有单项工程，统一审核所有班组长数据
- **分包独立项目**: 分包单位承担的工作作为独立单项工程，分包班组长为指定负责人，金卓 PM 统一审核
- **班组灵活变动**: 班组非固定编制，当日实际进场人员以考勤记录为准
- **备案人员项目部级**: 人员清单按项目部级维护，同一人员允许跨项目
- **角色互斥**: 项目经理不可兼任班组长；资料员与班组长可能兼任（少见但支持）
- **技术人员**: 项目部技术人员根据项目经理口头指令，在 PC 后台创建项目和配合配置工程量指标，不参与数据审核，不属于管理层级
- **小规模项目代行PM**: 小规模项目（如定向钻）中，分包的班组长可能代行现场项目经理职责。此时在项目创建时灵活指定该班组长同时拥有 PM 审核权限，审核链路不变（代行 PM 的审核数据仍归入该项目部统计）。该场景由金卓 PM 在项目配置时手动授权，系统不自动判断
- **班组长更换**: 施工过程中班组长可能因人员变动被更换。原班组长的历史数据保留且归属不变（仍标记为原班组长提交），新班组长接手后的数据标记新班组长。PM 审核记录不因班组长更换而失效

### 3.2 角色适配与项目解析 `[V1.1]`

所有功能页面（安全考勤、进度工效、材料设备、施工记录）均需支持不同角色的项目解析逻辑：

| 角色 | 项目解析行为 | 页面表现 |
|------|-------------|---------|
| 班组长 | 自动匹配其负责的单项工程 | 顶部显示项目名称（只读） |
| 项目经理 | 显示项目选择下拉框 | 顶部显示 `ProjectSelector` 组件 |
| 管理员 | 显示项目选择下拉框 | 顶部显示 `ProjectSelector` 组件 |
| 资料员 | 显示项目选择下拉框 | 顶部显示 `ProjectSelector` 组件 |

**公共组件 `ProjectSelector`**:
- 接受 `projects` 列表和 `onSelect` 回调
- 渲染为下拉选择框，显示所有可访问项目名称
- 用户切换项目时，`onSelect` 触发，页面数据刷新为新项目数据
- 班组长不显示选择器，自动加载其负责项目

**模拟拍照组件 `PhotoCapture`** `[V1.1]`:
- 用于原型演示阶段的照片模拟交互
- 用户点击照片区域 → 弹出底部选择面板（"拍照"/"从相册选择"）
- 选择后显示 300ms 加载动画，然后展示预设图片（picsum.photos），叠加当前日期时间水印
- 支持多次拍摄，最多 3 张照片
- 接受 `onPhotoTaken: (urls: string[]) => void` 回调

> **注意**: `PhotoCapture` 为原型演示专用组件。生产版本将替换为真实相机/文件上传 API。

#### 3.3.2 功能清单

| 功能项 | 描述 | 操作端 | 备注 |
|--------|------|--------|------|
| 班前早会发起 | 班组长在 APP 上发起当日早会 | APP | 每日必做 |
| 分类安全交底 | 根据作业类型选择对应交底模板（高空、动火、有限空间等） | APP | 模板由 PC 后台管理 |
| 手写电子签名 | 班组长在手机屏幕上手写签名确认安全交底 | APP | 仅班组长签名，施工人员不需逐一签名 |
| 考勤确认 | 班组长从备案人员列表手动勾选参会人员 | APP | 一期方案：手动勾选 |
| 早会拍照 | 拍摄早会现场照片，系统自动记录 GPS + 时间 | APP | 上限 1 张/日。原型阶段使用 `PhotoCapture` 模拟拍照 `[V1.1]` |
| 高风险作业记录 | 记录开工/完工时间、文字描述 | APP | 无网络时允许开工，事后补录 |
| 审核确认 | PM 查看早会数据，确认/退回/补充 | APP/PC | 按模块分别审核 |
| 拍照前置验证 `[V1.1]` | 安全签到步骤1中，拍照完成后才能进入下一步 | APP | 未拍照时"下一步"按钮禁用 |
| 角色适配 `[V1.1]` | 非班组长用户进入安全签到时显示项目选择器 | APP | 选择项目后加载该项目成员作为签到列表 |

> **跨项目考勤去重**: 同一人员允许跨项目参与（备案人员项目部级管理），但同一天同一人员只能被一个班组长勾选为参会人员。如果张三同时参与 A 项目和 B 项目，系统在考勤提交时校验：若张三当天已在 A 项目被勾选参会，B 项目班组长勾选时系统提示"该人员今日已在 XX 项目考勤"。由 PM 根据实际情况决定是否允许重复考勤（如半天转场场景），PM 有权手动放行。

#### 3.3.3 考勤方案（分期）

| 阶段 | 方案 | 硬件成本 | 防替代能力 |
|------|------|----------|------------|
| 一期 | 拍照 + GPS + 班组长手动勾选 | 零 | 依赖班组长诚信 |
| 二期 | 评估独立指纹打卡机（500-2000元/台） | 低 | 强 |

> 一期备案人员信息不录入指纹数据，指纹打卡为二期评估项，数据模型已预留指纹字段。

### 3.4 进度与工效管理

#### 3.4.1 业务流程

## 4. 项目经理审核机制

### 4.1 审核操作

| 操作 | 说明 |
|------|------|
| 审核通过 | 查看班组长提交数据，确认无误后通过 |
| 退回修改 | 数据有问题，退回班组长修改后重新提交 |
| 补充填写 | PM 自己补充数据或说明 |

### 4.2 数据修正规则

审核通过后**不允许删除或直接修改**原记录。需要修正时，追加一条"修正记录"说明更正内容和原因。系统保留完整审计轨迹（原记录 + 修正记录）。

```
原始记录: 焊接完成 100m ──── 审核通过 ──── 锁定
                                              │
                                    发现数据有误
                                              │
修正记录: 实际焊接完成 80m               追加修正记录
          原因: 丈量误差                   (保留原记录)
                                              │
                                    完整审计轨迹:
                                    原记录 + 修正记录
```

### 4.3 时效管理

- 审核时效不严格，几天内确认即可
- **超过 7 天未审核**: 系统自动通知项目管理部（通过 APP/PC 后台待办/异常列表展示，不做独立消息推送）
- **通知接收人定义**: "项目管理部"指金卓公司层面的项目管理职能部门（非卓裕/港华管理层）。通知仅在金卓 PM 的上级管理层待办列表中置顶显示，不升级到卓裕/港华管理层，不发送独立推送。通知内容包含：超时项目名称、班组长、模块类型、提交日期、超时天数
- 施工单位每周只休息一天，PM 有足够时间处理审核

### 4.4 审核范围

覆盖全部四个模块：考勤数据、进度记录、材料登记、施工记录。按模块分别审核，不强制一次性审核全部。

### 4A.2 AI 智能审核

**目标用户**: 项目经理（PC 端 + 移动端审核）

**核心能力**: 班组长提交记录后，系统自动运行 6 条规则进行预审，将记录分为"正常/疑似异常/明显问题"三类，辅助项目经理高效审核。

#### 4A.2.1 规则引擎（6 条审计规则）

| 规则 ID | 规则名称 | 检测逻辑 | 严重度 |
|---------|---------|---------|--------|
| `spike` | 数据突变 | 当日完成量 > 近 7 天日均 × 3 | HIGH |
| `attendance_mismatch` | 考勤矛盾 | 完成量 > 出勤人数 × 人均工效 × 1.5 | HIGH |
| `material_anomaly` | 材料异常 | 领料量 > 剩余需求量 × 1.2 | MEDIUM |
| `compliance_gap` | 合规缺失 | 高风险作业无安全交底记录 | HIGH |
| `cert_expired` | 证件过期 | 签到人员证件到期日 < 当前日期 | HIGH |
| `progress_deviation` | 进度偏离 | 实际进度与计划进度偏差 > 20% | MEDIUM |

#### 4A.2.2 预审流程

```
班组长提交 DailyRecord
        │
        ▼
  规则引擎运行（6条规则并行）
        │
        ├── 全部通过 → 标记"正常" → PM 审核列表中显示 ✅
        │
        ├── 部分触发 MEDIUM → 标记"疑似异常" → 显示 ⚠️ + 原因说明
        │
        └── 触发 HIGH → 标记"明显问题" → 显示 🔴 + 详细原因 + 建议操作
        │
        ▼
  PM 审核工作台展示分类统计:
  · 正常: 12 条  →  [一键批量通过]
  · 疑似异常: 3 条 →  逐条查看
  · 明显问题: 1 条 →  逐条查看 + 退回/通过
```

#### 4A.2.3 功能清单

| 功能项 | 描述 | 操作端 |
|--------|------|--------|
| 预审分类统计 | 展示正常/疑似异常/明显问题的数量统计卡片 | PC |

### 4A.4 自然语言数据查询

**目标用户**: 项目经理、管理层（PC 端）

**核心能力**: 在 PC 端搜索栏输入自然语言问题，系统自动转换为数据查询并返回自然语言回答 + 关键数据卡片。

#### 4A.4.1 支持的查询类型

| 查询类型 | 示例 | 返回内容 |
|---------|------|---------|
| 进度查询 | "XX路项目现在进度怎么样" | 整体进度百分比 + 各工序进度列表 |
| 人员查询 | "今天张三班组有几个人出勤" | 出勤人数 + 人员列表 |
| 材料查询 | "这个月领了多少镀锌钢管" | 材料汇总数量 + 领料明细 |
| 安全查询 | "本周安全交底做了几次" | 交底次数 + 类型分布 |
| 对比查询 | "XX路和YY路哪个进度快" | 两项目进度对比 |

#### 4A.4.2 功能清单

| 功能项 | 描述 | 操作端 |
|--------|------|--------|
| NL 查询入口 | PC 端顶部搜索栏增强为自然语言查询输入框 | PC |
| Text-to-Query 转换 | 将自然语言转换为结构化查询参数 | 系统 |
| 查询执行 | 基于转换后的参数查询本地数据 | 系统 |
| 自然语言回答 | 将查询结果渲染为自然语言回答 + 数据卡片 | PC |

### 4A.5 AI 服务层

## 7. 非功能需求

### 7.1 离线模式

| 场景 | 行为 |
|------|------|
| 在线 | 全功能可用，数据实时同步 |
| 离线 | **只读模式**，仅查看已下载的数据，不能新增记录 |
| 网络恢复 | 自动同步，无感切换 |
| 高风险作业 | 无网络时允许开工，事后在线补录 |

### 7.2 手写签名

- 班组长在手机屏幕上手写签名
- 港华安全管理体系认可手机手写签名作为有效记录
- 用于安全交底记录和高风险作业确认单
- 仅班组长签名，施工人员不需逐一签名

### 7.3 照片管理

| 模块 | 每日上限 | 说明 |
|------|----------|------|
| 安全考勤 | 1 张 | 早会现场照片。原型阶段使用 `PhotoCapture` 模拟拍照 `[V1.1]` |
| 进度记录 | 5 张 | 施工进展照片 |
| 施工记录 | 10 张 | 现场施工照片 + 竣工草图 |
| 签字文件 | 不限 | 存档用途 |

> `[V1.1]` **原型阶段照片交互**: 所有照片区域使用 `PhotoCapture` 模拟拍照组件。用户点击后弹出底部选择面板（"拍照"/"从相册选择"），选择后延迟 300ms 显示预设图片（picsum.photos），图片叠加当前日期时间水印。单次拍照最多 3 张。生产版本将替换为真实相机/文件上传 API。

### 7.4 性能要求

| 指标 | 要求 |
|------|------|
| APP 启动 | 冷启动 < 3 秒 |
| 页面加载 | < 2 秒（在线）/ < 1 秒（离线缓存） |
| 数据提交 | < 3 秒（含照片上传） |
| 照片压缩 | 上传前自动压缩，单张 < 500KB |
| 离线缓存 | 保留最近 30 天的已下载数据 |
| 并发用户 | 支持 50 人同时在线（试点规模） |
| `[AI Phase 1]` Mock LLM 响应 | < 500ms（关键词匹配 + 模板生成） |
| `[AI Phase 1]` 真实 LLM 响应 | < 5 秒（GLM API 调用，首 token 返回 < 2 秒） |
| `[AI Phase 1]` AI 浮窗首屏渲染 | < 300ms（React Portal 挂载） |
| `[AI Phase 1]` 规则引擎预审 | < 1 秒（6 条规则并行执行） |
| `[AI Phase 1]` 上下文窗口 | 最近 10 条消息（超出自动截断最早消息） |

### 7.6 兼容性

| 项目 | 要求 |
|------|------|
| APP 平台 | Android 8.0+ |
| 屏幕适配 | 5.5 寸 ~ 6.7 寸手机 |
| PC 浏览器 | Chrome、Edge、Firefox 最新两个版本 |
| 网络环境 | 4G/5G/WiFi，弱网有降级方案 |

#### 7.6.1 BYOD 适配策略

班组长使用自有安卓手机，不统一配发设备。分包单位班组长同样适用 BYOD 场景。系统需做以下适配：

| 策略 | 说明 |
|------|------|
| 屏幕适配 | 支持 5.5~6.7 寸主流屏幕，手写签名区域按屏幕宽度自适应 |
| 存储友好 | 照片自动压缩至 500KB 以内，本地缓存仅保留 30 天，避免占用用户手机空间 |
| 低端机兼容 | 安卓 8.0+ 起步，避免依赖最新系统 API，确保中低端机型流畅运行 |
| 电量优化 | GPS 仅在拍照时采集一次，不做持续定位；后台同步仅在充电+WiFi 时自动执行 |
| 数据安全 | 本地数据加密存储，APP 卸载后数据不可恢复；不访问用户个人数据（通讯录、相册仅限用户主动选择） |
| 话费补助 | 项目部给予班组长话费补助（含流量），不作为系统功能但影响用户接受度 |
