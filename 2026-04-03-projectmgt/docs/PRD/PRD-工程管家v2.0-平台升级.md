# 工程管家 V2.0 — 从"日报填报工具"到"工程管理平台"

> 版本: V2.0 | 日期: 2026-04-04 | 基于 V1.1 原型 + AI Phase 1 的升级规划

---

## 一、升级背景

### 1.1 当前系统定位

工程管家 V1.1 是一个面向班组长的**日报填报工具**: 考勤签到、施工进度、材料领退、施工记录四大模块。AI Phase 1 增加了对话填表、智能审核、每日简报、自然语言查询。

从顶级工程施工单位的视角看，V1.1 解决了**信息采集**的第一步，但距离真正的"工程管理平台"存在根本性差距。

### 1.2 核心差距

```

│                   施工管理全维度                               │
│                                                              │

│                                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐     │
│  │ 事前计划  │  │ 事中控制  │  │ 事后分析  │  │ 行业合规  │     │
│  │          │  │          │  │          │  │          │     │
```

### 1.3 升级愿景

| 维度 | V1.1 (当前) | V2.0 (目标) |
|------|------------|------------|
| 定位 | 日报填报工具 | 工程管理平台 |
| 核心用户 | 班组长 | 项目全角色协同 |
| 数据流 | 事后记录 | 事前计划 + 事中控制 + 事后分析 |
| 安全管理 | 班前交底签到 | 全流程安全管理闭环 |
| 质量管理 | 无 | 检验批验收 + 质量缺陷跟踪 |
| 成本管理 | 无 | 预算对比 + 成本预警 |
| 进度管理 | 填数字 | 工序级排程 + 关键路径 |
| 行业适配 | 通用 | 燃气管道专业化 |
| 网络依赖 | 必须在线 | 离线优先 |

## 三、Phase 2: 质量安全管理 (P0 — 合规刚需)

> 不做 = 系统无法替代任何纸质流程，停留在辅助工具层面

### 3.1 质量检验批管理

**为什么是 P0**: 建设工程质量管理条例要求每个检验批必须有验收记录。燃气管道工程按 CJJ 33 规范，每个工序（开挖、管道安装、焊接、探伤、打压、回填）都有对应的检验批标准。目前系统无任何质量管理功能。

#### 3.1.1 检验批验收流程

```
班组长提交 ←→ 质量员检查 ←→ 监理验收 ←→ 签字确认
    │              │              │            │
    ▼              ▼              ▼            ▼
  填报数据     现场检查       核对规范      合格/不合格
  影像资料     合格/整改      通过/退回     电子签名
```

**功能要求**:
- **检验批模板**: 按 CJJ 33 规范预置检验批表格（管沟开挖、管道安装、阀门安装、管道焊接、管道防腐、管道吹扫、强度试验、气密性试验、回填等）
- **三方验收**: 班组长填报 → 质量员自检 → 监理验收，三方电子签名
- **整改闭环**: 不合格检验批自动生成整改工单，整改后重新提交验收
- **影像资料**: 每个检验批必须附带照片（施工前、施工中、完成后），照片带时间戳+GPS
- **统计报表**: 按工序统计合格率、一次验收通过率、整改率

#### 3.1.2 质量缺陷跟踪

**功能要求**:
- **缺陷登记**: 任何人可上报质量缺陷（文字描述 + 照片 + 位置）
- **缺陷分类**: 按严重程度（A 级停工/B 级整改/C 级记录）自动分类
- **整改跟踪**: 指派责任人 → 限期整改 → 整改验证 → 关闭
- **缺陷分析**: AI 自动分析缺陷模式（如某班组焊接缺陷率偏高），在简报中预警

#### 3.1.3 材料复试管理

**功能要求**:
- **复试台账**: 跟踪进场材料的复试状态（已送检/报告已出/合格/不合格）
- **自动提醒**: 材料复试报告超期未出时自动提醒
- **关联追溯**: 材料复试报告关联到使用该材料的施工段，不合格时标记影响范围

### 3.2 安全管理升级

**为什么是 P0**: 安全生产法要求定期安全检查、隐患排查整改闭环。当前仅有班前交底签到，远不够。

#### 3.2.1 安全检查评分

**功能要求**:
- **检查模板**: 预置 JGJ 59 建筑施工安全检查标准评分表（10 大类 168 项）
- **移动端检查**: 班组长/安全员在手机上逐项打分，支持拍照记录
- **自动评分**: 按 JGJ 59 标准自动计算总分和等级（优良/合格/不合格）
- **整改通知**: 不合格项自动生成整改通知，推送责任人

#### 3.2.2 安全隐患排查整改闭环

```
┌─────────────────────────────────────────────────────┐
│           安全隐患排查整改闭环                         │
│                                                     │
│  发现隐患 ──▶ 登记上报 ──▶ 评估分级 ──▶ 指派整改     │
│      │                                      │       │
│      │          ┌───────────────────────────┘       │
│      │          ▼                                   │
│      │      限期整改 ──▶ 整改验证 ──▶ 关闭归档       │
│      │                       │                      │
│      │                       ▼                      │
│      │                  整改不合格 ──▶ 升级处理       │
│      │                                          │   │
│      └─────────────── 统计分析 ◀────────────────┘   │
└─────────────────────────────────────────────────────┘
```

**功能要求**:
- **隐患登记**: 班组长/安全员/任何人可上报隐患（照片 + 描述 + 位置 + 风险等级）
- **四级分类**: 一般隐患/较大隐患/重大隐患/特别重大隐患，按等级触发不同审批流程
- **限期整改**: 系统自动按等级设置整改时限（一般3天/较大7天/重大15天/特别重大立即停工）
- **超期预警**: 整改超期自动升级通知（通知项目经理、安全总监）
- **统计分析**: 隐患类型分布、按班组统计、整改及时率、重复隐患识别

#### 3.2.3 安全培训记录

**功能要求**:
- **培训计划**: 安全员制定月度安全培训计划
- **签到管理**: 培训现场电子签到（复用现有考勤功能）
- **效果评估**: 培训后简短问答（3-5题），系统自动评分
- **档案管理**: 每人安全培训档案（总学时、最近培训日期、待完成计划）

### 3.3 图纸版本管理

**为什么是 P0**: 施工必须使用最新版图纸。用错图纸导致返工是最大的成本浪费源。平均一个燃气管道项目有 20-50 次图纸变更。

**功能要求**:
- **图纸上传**: 资料员/技术人员上传施工图纸（PDF/DWG），自动提取版本号
- **版本对比**: 新旧图纸并排对比，自动标记变更区域
- **变更通知**: 图纸更新时自动通知相关班组长，班组长必须确认已阅
- **关联工序**: 图纸版本关联到对应工序，施工时系统自动显示最新版图纸
- **离线缓存**: 关键图纸预下载到手机，离线可查看

## 四、Phase 3: 成本进度管控 (P1 — 管理提升)

### 4.1 成本管控仪表盘

**为什么是 P1**: 施工企业利润率 3-8%，成本超支是项目经理最关心的问题。

#### 4.1.1 预算管理

**功能要求**:
- **预算录入**: 项目立项时录入合同预算（按人工/材料/机械/管理费分项）
- **预算分解**: 将总预算分解到各工序（开挖预算、焊接预算、打压预算等）
- **预算调整**: 变更签证导致预算调整时，记录调整原因和审批链
- **预算对比**: 实时显示"已完成产值 vs 已发生成本 vs 合同预算"

#### 4.1.2 成本预警

```
┌──────────────────────────────────────────────┐
│          成本监控仪表盘                        │
│                                              │
│  ┌─────────────────────────────────────────┐ │
│  │  合同总价    已完成产值    已发生成本     │ │
│  │  580万       210万(36%)    198万(34%)    │ │
│  │  ████████    ████████░░    ███████░░░    │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  ┌─────────────────────────────────────────┐ │
│  │  分项成本预警                            │ │
│  │  ✅ 人工费  实际 45万 / 预算 50万 (90%)  │ │
│  │  ⚠️ 材料费  实际120万 / 预算130万 (92%)  │ │
│  │  🔴 机械费  实际 35万 / 预算 30万 (117%) │ │
│  │  ✅ 管理费  实际 12万 / 预算 20万 (60%)  │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  AI 建议: 机械费超预算17%，主要原因是...      │
└──────────────────────────────────────────────┘
```

**功能要求**:
- **实时对比**: 按成本科目（人工/材料/机械/管理费）实时显示预算执行率
- **超支预警**: 某科目执行率超 90% 自动黄色预警，超 100% 自动红色预警
- **趋势预测**: AI 基于当前消耗速率预测最终成本（预测完成成本 EAC）
- **成本日报**: 每日自动生成成本简报，推送项目经理

### 4.2 工序级进度管理

**为什么是 P1**: 当前进度录入只是"填数字"，不能表达工序间的逻辑关系。燃气管道施工有严格的工序顺序: 开挖 → 管道安装 → 焊接 → 探伤 → 打压 → 吹扫 → 回填 → 附属设施。

#### 4.2.1 工序依赖与关键路径

**功能要求**:
- **工序网络**: 定义工序间的依赖关系（FS/SS/FF/SF 四种逻辑关系）
- **关键路径**: 自动计算关键路径，标识影响总工期的关键工序
- **里程碑**: 设置关键节点（开工、管道就位、打压合格、通气、竣工），到期自动提醒
- **进度预警**: 关键工序延误时自动预警，非关键工序延误超过自由时差时也预警

#### 4.2.2 可视化排程

**功能要求**:
- **甘特图**: PC 端显示项目甘特图（计划 vs 实际对比）
- **施工日历**: 移动端显示本周施工日历（今天该做什么、明天计划做什么）
- **资源直方图**: 显示各时段的人力/机械需求，帮助资源平衡

### 4.3 沟通通知体系

**功能要求**:
- **消息推送**: 审核结果、图纸变更、安全隐患、整改通知等实时推送
- **@提醒**: 在施工记录/问题讨论中可 @相关人，被 @人收到推送
- **公告通知**: 项目经理可发项目公告，全员收到
- **消息分类**: 按类型分组（待办/审核/安全/系统），支持已读/未读标记
- **超时升级**: 审核超 7 天未处理自动升级通知

### 4.4 离线优先架构

**为什么是 P1**: 施工现场网络条件极差（地下室无信号、偏远工地 3G/4G 不稳定）。当前系统必须在线使用，在现场根本用不起来。

**技术方案**:
```
┌──────────────────────────────────────────────────┐
│              离线优先架构                          │
│                                                  │
│  ┌───────────┐     ┌───────────┐                │
│  │ 移动端    │     │   PC 端   │                │
│  │           │     │           │                │
│  │ ┌───────┐ │     │ ┌───────┐ │                │
│  │ │本地 DB│ │◄───▶│ │云端 DB│ │                │
│  │ │IndexDB│ │同步 │ │服务端 │ │                │
│  │ └───┬───┘ │     │ └───────┘ │                │
│  │     │     │     │           │                │
│  │ ┌───▼───┐ │     │           │                │
│  │ │Service│ │     │           │                │
│  │ │Worker│ │     │           │                │
│  │ └───────┘ │     │           │                │
│  └───────────┘     └───────────┘                │
│                                                  │
│  在线: 实时同步                                   │
│  弱网: 后台队列，有网自动上传                      │
│  离线: 本地读写，联网后冲突合并                     │
└──────────────────────────────────────────────────┘
```

**功能要求**:
- **Service Worker**: 离线时所有表单可正常填写，数据存入 IndexedDB
- **自动同步**: 恢复网络后自动上传本地数据，下载最新数据
- **冲突处理**: 多人同时修改同一条记录时的合并策略（最后写入 wins + 人工确认）
- **数据预加载**: WiFi 环境下预下载项目数据、图纸、模板，确保离线可用
- **同步状态指示**: 顶部显示同步状态（已同步/同步中/离线模式/有冲突）

## 五、Phase 4: 燃气管道专业化 (P2 — 行业深度)

### 5.1 焊口追踪管理

**为什么重要**: 燃气管道焊接质量直接关系安全。每道焊口从焊接 → 探伤 → 返修 → 最终合格，全流程必须可追溯。

**功能要求**:
- **焊口编号**: 自动按规范生成焊口编号（管线号 + 桩号 + 序号）
- **焊工绑定**: 每道焊口绑定焊工姓名和资格证书编号，自动验证焊工资格
- **焊接参数**: 记录焊接方法、焊材型号、焊接电流/电压、预热温度等
- **无损检测**: 关联射线检测(RT)/超声波检测(UT)报告，记录检测结果和缺陷类型
- **返修管理**: 不合格焊口自动生成返修工单，记录返修次数（超过2次返修需报批）
- **追溯链条**: 任何焊口可通过编号追溯到焊工、检测报告、返修记录

### 5.2 管道试压管理

**功能要求**:
- **试压方案**: 按规范生成试压方案（强度试验压力、稳压时间、合格标准）
- **实时记录**: 连接压力表自动记录压力变化曲线（或人工定时录入）
- **自动判定**: 系统根据 CJJ 33 标准自动判定合格/不合格
- **电子签名**: 试压合格后三方签字（施工方、监理方、建设方）

### 5.3 防腐补口管理

**功能要求**:
- **防腐等级**: 按设计要求记录防腐等级（普通/加强/特加强）
- **补口检验**: 讘录补口外观检查、电火花检漏结果
- **厚度检测**: 记录防腐层厚度检测数据，自动判定是否达标

## 六、Phase 5: AI 预测分析 (P2 — 智能升级)

### 6.1 工期预测

**功能要求**:
- **基于历史数据**: 分析同类型项目的历史工期数据，预测当前项目的完工日期
- **关键路径预警**: 关键工序延误时，自动计算对总工期的影响天数
- **赶工建议**: AI 基于资源可用性和工序逻辑，生成赶工方案（增加人力/加班/调整工序顺序）
- **概率分布**: 显示完工日期的概率分布（乐观/最可能/悲观三种场景）

### 6.2 成本预警

**功能要求**:
- **EAC 预测**: 基于当前消耗速率预测最终成本（Estimate at Completion）
- **成本趋势**: 按周显示成本趋势曲线，预判超支风险
- **异常检测**: AI 识别成本异常模式（如某天材料费突增），自动生成分析报告

### 6.3 安全风险预判

**功能要求**:
- **风险因子模型**: 基于天气、工期压力、人员疲劳度、历史事故数据评估安全风险等级
- **高危场景识别**: 识别高危场景（深基坑作业 + 雨天 + 赶工期 = 高风险）并推送预警
- **安全评分**: 给每个班组/项目动态安全评分，低于阈值触发安全检查

### 6.4 质量缺陷模式识别

**功能要求**:
- **缺陷聚类**: AI 自动对质量缺陷进行分类聚类，识别系统性质量问题
- **根因分析**: 基于缺陷数据和相关因素（材料批次、焊工资质、天气条件）进行根因分析
- **预防建议**: AI 生成质量改进建议（如"X批次管材焊接缺陷率偏高，建议抽样复检"）

### 7.2 离线优先方案

- **前端**: Service Worker + IndexedDB + Background Sync API
- **数据同步**: 增量同步 + 版本向量冲突检测
- **文件缓存**: 图纸/照片使用 Cache API 预缓存

### 7.3 安全要求

- **认证**: JWT Token + Refresh Token
- **权限**: RBAC（角色 + 资源 + 操作三级权限）
- **审计**: 所有操作记录审计日志（谁、什么时候、做了什么、结果如何）
- **加密**: 敏感数据传输 HTTPS，存储 AES-256
- **合规**: 等保二级（工程管理系统属于一般信息系统）

## 九、关键风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 后端引入复杂度高 | 开发周期拉长 | Phase 2 先用 BaaS（Supabase）快速上线，Phase 3 再自建 |
| 离线同步冲突频繁 | 数据不一致 | 采用"最后写入 wins + 关键字段人工确认"策略 |
| 图纸文件体积大 | 移动端存储/加载慢 | 图纸按页缓存 + 渐进式加载 + WiFi 预下载 |
| AI 预测准确率不足 | 用户不信任 | 先展示置信度，同时提供人工修正入口 |
| 燃气行业规范复杂 | 功能设计偏差 | 请燃气公司技术部门参与验收标准制定 |
| 移动端性能瓶颈 | 体验差 | 纯原生关键页面（相机、签名），其余 WebView |
