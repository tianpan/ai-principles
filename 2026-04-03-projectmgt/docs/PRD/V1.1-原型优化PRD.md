# 工程管家 V1.1 原型优化 PRD

> 版本: 1.0 | 日期: 2026-04-04 | 状态: 待实施

## 1. 背景与目标

V1.0 原型已完成基础框架搭建（APP端4大模块 + PC端4大模块），但经过实际测试发现多个阻断性问题和数据缺失问题。原型作为演示工具，**首要目标是让每个流程都能端到端跑通，数据丰富、交互完整**，让评审者能直观理解系统逻辑。

### V1.0 已知问题清单

| # | 问题 | 严重性 | 根因 |
|---|------|--------|------|
| 1 | PC 项目管理点进项目详情报错 | **阻断** | `/pc/projects/[id]/page.tsx` 路由文件缺失 |
| 2 | 安全签到无法进入下一步 | **阻断** | 1) 照片区域是静态占位符，无上传交互 2) 班组长以外的角色看不到项目成员 |
| 3 | 施工进度页面数据为空 | **阻断** | `useState(initialItems)` 在 hydration 期间捕获空数组，hydration 后不更新 |
| 4 | 材料设备页面全手填，无辅助 | **体验差** | 领料/退料/设备/采买均无预设数据、无历史记录参考 |
| 5 | 所有页面 mock 数据量太少 | **体验差** | 每个模块仅1-2条记录，无法展示丰富状态 |
| 6 | 照片上传全为占位符 | **体验差** | 安全、进度、施工记录的照片区域均无交互 |
| 7 | 表单无验证 | **体验差** | 施工记录可提交空表单，材料可提交空行 |
| 8 | 角色权限不完整 | **体验差** | 项目经理/管理员登录后大部分功能不可用 |

### V1.1 核心目标

1. **所有流程端到端跑通** — 从登录到完成每一个业务操作，无阻断
2. **数据丰富可演示** — 每个页面都有足够的模拟数据展示各种状态
3. **交互体验接近真实** — 照片用模拟数据展示，表单有合理验证和默认值
4. **角色全覆盖** — 至少支持班组长（移动端）和项目经理/管理员（PC端）两种角色路径

### 2.2 安全签到流程修复

**问题拆解**:

1. **照片不可交互**: 当前是 `<div>` 占位符，无 `<input type="file">` 或模拟上传逻辑
2. **非班组长角色无法使用**: `getProjectsByTeamLeader(currentUser.id)` 对项目经理返回空数组

**方案**:

**照片区域改造**: 模拟拍照体验。点击照片区域 → 弹出选择面板（模拟）→ 选择后显示预设照片（用 placeholder 图片），状态标记为"已拍照"。

```
拍照前:                    拍照后:
┌──────────────┐          ┌──────────────┐
│              │          │ ┌──────────┐ │
│   📷         │   →      │ │ 班前会   │ │
│   点击拍照    │          │ │ 照片     │ │
│              │          │ └──────────┘ │
│              │          │   ✓ 已拍照    │
└──────────────┘          └──────────────┘
```

**角色适配**: 增加项目选择器。当用户有多个项目或以管理员身份查看时，显示项目下拉选择而非自动匹配第一个项目。

```
班组长登录:  自动匹配 myProjects[0]（保持现有逻辑）
项目经理登录: 显示项目选择下拉框，列出所有项目
管理员登录:   显示项目选择下拉框，列出所有项目
```

**步骤验证逻辑调整**:

| 步骤 | 当前条件 | 调整后条件 |
|------|---------|-----------|
| Step 0 (拍照+签到) | 有选中成员 | 有选中成员 **且** 已模拟拍照 |
| Step 1 (安全交底) | 已选交底模板 | 不变 |
| Step 2 (签名) | 始终可下一步 | 不变 |
| Step 3 (确认) | 始终可下一步 | 不变 |

### 2.3 施工进度页面数据刷新

**问题**: `useState(initialItems)` 在组件首次渲染时捕获空数组，hydration 完成后 `initialItems` 更新但 `items` state 不跟随更新。

**方案**: 用 `useEffect` 监听 `currentProject` 变化，同步更新 `items` state:

```tsx
// 修改前
const [items, setItems] = useState(initialItems);

// 修改后
const [items, setItems] = useState(initialItems);
useEffect(() => {
    setItems(initialItems);
}, [currentProject?.id]);
```

## 3. 数据丰富化

### 3.1 设计原则

- 覆盖所有状态：已通过、待审核、已退回
- 覆盖多天数据：至少 7 天历史 + 今天
- 每个项目 × 每个模块 都有数据
- 数据逻辑自洽：累计进度不超过目标量、签到人数与项目成员对应

### 3.2 Daily Records 扩充方案

**当前**: 12 条记录，集中在 2 天（04-01, 04-02）

**目标**: 约 60-70 条记录，覆盖 7 天（03-28 ~ 04-03），3 个项目 × 4 个模块

| 项目 | 考勤 | 进度 | 材料 | 施工记录 | 小计 |
|------|------|------|------|---------|------|
| 项目1 (张三) | 7天×1=7 | 7天×1=7 | 5条(含1退回) | 4条 | 23 |
| 项目2 (李四) | 7天×1=7 | 5天×1=5 | 3条 | 2条 | 17 |
| 项目3 (王五) | 5天×1=5 | 3天×1=3 | 2条(含1已退回) | 2条 | 12 |
| **合计** | 19 | 15 | 10 | 8 | **52** |

**状态分布**:

| 状态 | 数量 | 说明 |
|------|------|------|
| 已通过 | ~35 | 历史已审核记录 |
| 待审核 | ~8 | 近1-2天待审记录 |
| 已退回 | ~3 | 含退回原因的记录 |
| 草稿 | ~6 | 今天的未提交记录 |

**进度数据逻辑**:

项目1 "中压管线焊接" (目标 1200 米):
- 03-28: 累计 60m
- 03-29: 累计 130m
- 03-30: 累计 220m
- 03-31: 累计 310m
- 04-01: 累计 390m (当日 80m)
- 04-02: 累计 480m (当日 90m)
- 04-03: 累计 570m (当日 90m, 今日可输入)

### 3.3 考勤数据丰富化

每条考勤记录包含:
- `photoUrl`: 使用 picsum.photos 模拟图片
- `gpsLocation`: 南京地区真实坐标微调
- `safetyBriefingType`: 轮换使用不同交底类型
- `attendeeIds`: 随机从项目成员中选取 3-6 人
- `signatureUrl`: 占位签名

### 3.4 材料数据丰富化

领料记录应包含:
- 规范的领料单号格式: `MR-YYYYMMDD-NNN`
- 合理的材料和数量:
  - DN100镀锌钢管、DN200无缝钢管、PE管DN90/DN200
  - 焊条、阀门、法兰、弯头
- 设备租赁: 吊车、挖掘机、电焊机，含台班数
- 退料记录: 退回多余材料，有退料单号
- 采买记录: 乙供材采购（如螺丝、密封胶等辅料）

## 4. 交互优化

### 4.1 照片功能模拟

所有照片区域统一使用"模拟拍照"模式:

1. 点击照片区域 → 弹出选择弹窗（"拍照" / "从相册选择"）
2. 选择后延迟 500ms 模拟处理 → 显示预设照片
3. 照片上叠加时间戳水印（模拟）
4. 可追加多张照片（上限3张）

预设照片使用 `https://picsum.photos/seed/{random}/{width}/{height}` 生成。

### 4.2 材料设备页面优化

**当前问题**: 四个 tab（领料/退料/设备/采买）全部手动填写，无辅助。

**优化方案**:

1. **常用材料快捷选择**: 在材料名称输入框旁加"+"按钮，弹出常用材料列表:
   - DN100镀锌钢管、DN200无缝钢管、PE管DN90、PE管DN200
   - 焊条E4303、球阀DN100、法兰DN200、弯头90°
   - 选择后自动填充名称和规格

2. **领料单号自动生成**: 格式 `MR-YYYYMMDD-NNN`，自动递增

3. **"复制昨天"功能增强**: 复制后保留数量为空，让用户填写今日数量

4. **设备 tab 预设选项**: 设备类型下拉（吊车、挖掘机、压路机、电焊机、发电机），规格联动

### 4.3 表单验证

| 页面 | 验证规则 |
|------|---------|
| 安全签到 | 至少1位签到成员 + 已拍照 + 已选交底模板 |
| 施工进度 | 至少1项工程量输入 > 0 |
| 材料设备 | 每行材料名称和数量必填 |
| 施工记录 | 至少选择记录类型 + 填写位置 |

提交时 Toast 提示具体缺失项。

## 6. 角色路由优化

### 6.1 当前问题

移动端所有功能页面（安全签到、施工进度、材料设备、施工记录）都使用 `getProjectsByTeamLeader(currentUser.id)` 获取当前用户的项目，只有"班组长"角色有项目数据。

### 6.2 方案

在移动端各功能页面增加角色适配逻辑:

```tsx
// 项目获取逻辑（统一提取到工具函数）
function getMyProject(currentUser: User): Project | undefined {
    if (currentUser.role === "班组长") {
        return getProjectsByTeamLeader(currentUser.id)[0];
    }
    // 项目经理/管理员：返回第一个项目（或增加选择器）
    return data.projects[0];
}
```

优先级: 班组长自动匹配 → 其他角色显示项目选择器。

### 6.3 PC 端权限

PC 端已经展示所有项目数据，不存在角色问题。确保:
- 项目经理登录 → 可查看所有项目、审核记录、查看报表
- 管理员登录 → 同上

## 8. 数据模型参考

### 8.1 现有模型（不变）

- User: id, name, phone, password, role, departmentId, status
- Project: id, name, departmentId, teamLeaderId, memberIds, workItems, ...
- Worker: id, departmentId, name, position, certifications
- Template: id, name, category, content
- DailyRecord: id, projectId, teamLeaderId, date, moduleType, status, ...

### 8.2 DailyRecord 模块类型

| moduleType | 对应字段 | 说明 |
|-----------|---------|------|
| 考勤 | attendance | 班前会签到 |
| 进度 | progress | 工程量完成 |
| 材料 | materials | 领料/退料/设备/采买 |
| 施工记录 | siteRecord | 工程量 + 影像 |

### 8.3 状态流转

```
草稿(新增) → 待审核 → 已通过
                    → 已退回 → (编辑后重新提交) → 待审核
```

## 9. 验收标准

1. **PC 端**: 以项目经理登录，每个导航页面（工作台、项目管理、审核工作台、报表中心）都有丰富数据，点进项目详情不报错
2. **移动端**: 以班组长登录，4个模块（安全签到、施工进度、材料设备、施工记录）每个都能走完全流程
3. **数据**: 每个页面至少展示 5+ 条有效数据，涵盖已通过/待审核/已退回三种状态
4. **交互**: 照片可模拟拍照，表单有验证提示，无空状态页面
5. **刷新**: 页面刷新后数据保持（localStorage 持久化）
